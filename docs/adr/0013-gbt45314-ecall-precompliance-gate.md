# ADR-0013: GB/T 45314 emergency-call pre-compliance gate

**Status:** Accepted.
**Date:** 2026-05-27
**Supersedes:** ADR-0012 for China emergency-call release decisions.

## Context

China's current in-vehicle emergency-call path is anchored by:

- **GB 45672-2025** `车载事故紧急呼叫系统`, published 2025-04-25 and implemented from 2027-07-01. It references the emergency-call system-level obligations.
- **GB/T 45314-2025** `道路车辆 免提通话和语音交互性能要求及试验方法`, published and implemented 2025-02-28. Section 5 defines emergency-call speech quality requirements for vehicles with emergency-call terminals.

GB/T 45314 uses HATS, POI, artificial mouth/ear, network simulator, and standard noise scenes. This repository cannot honestly certify those lab measurements from desktop WAV fixtures. What we can do is add a strict software pre-compliance gate so the ECNR chain is not released to vehicle/customer validation until it has passed objective proxies for the echo-cancellation and noise-suppression clauses.

## Decision

Add `conditions/gbt45314_ecall/` fixtures generated by `reference/gen_gbt45314_ecall_conditions.py`, extend `ecnr_eval --run` CSVs, and enforce them with `reference/check_gbt45314_ecall_gate.py`.

The gate is **blocking** for internal release to GB/T 45314 validation. It is not a replacement for third-party certification.

`ecnr_eval` also exposes the production RNNoise blend controls (`--ns-dry-blend` and `--ns-vad-blend`) so emergency-call presets can be swept with the same CSV schema. The gate must still be run on one release-candidate configuration at a time; passing one condition with a special one-off config is not a release pass.

## Clause Mapping

| GB/T 45314 area | Standard requirement | Software gate proxy |
|---|---|---|
| 5.1 delay | Driver `Trtd < 210 ms` | `frame_duration_ms <= 110 ms` implementation-delay proxy plus `rtf < 1.0` |
| 5.5.1 TCL | Nominal-volume `TCL >= 46 dB` | `erle_true_median_db >= 46 dB` on echo-only pass |
| 5.5.2 time-domain echo | Echo attenuation should remain stable | Per-frame ERLE timeline columns; visible in CSV |
| 5.5 initial convergence via 4.8.4 | 5 dB at 0/200 ms, 20 dB at 1000 ms, 40 dB from 1200 ms onward | `erle_initial_*_db` floors |
| 5.5.3 time-varying echo path | Echo performance increase/degradation no more than 6 dB | `erle_time_variation_db <= 6 dB` |
| 5.7 double-talk | Emergency-call send-side double-talk grade 2b or higher | `near_end_level_delta_median_db >= -12 dB` and `near_end_correlation >= 0.60` |
| 5.8.1 B2 no-speech noise | Transmitted noise level variation `< 10 dB` | `noise_level_range_db < 10 dB` on the B2 proxy condition |

## Conditions

`reference/gen_gbt45314_ecall_conditions.py` generates five deterministic conditions:

- `ecall_farend_quiet_tcl_convergence`: quiet far-end single-talk TCL/convergence.
- `ecall_farend_b1_road_convergence`: far-end single-talk with road-noise proxy.
- `ecall_timevarying_path`: abrupt cabin-path change for 5.5.3.
- `ecall_doubletalk_driver_minus6`: far-end echo plus near-end driver speech 6 dB below nominal.
- `ecall_b2_noise_only_stability`: HVAC-like B2 no-speech noise stability.

The WAVs are generated, not committed.

## Release Workflow

```sh
python3 reference/gen_gbt45314_ecall_conditions.py

./build/ecnr_eval \
  --run \
  --conditions conditions/gbt45314_ecall \
  --out /tmp/gbt45314_ecall.csv \
  --out-wavs /tmp/gbt45314_ecall_wavs \
  --agc

python3 reference/check_gbt45314_ecall_gate.py \
  --in-csv /tmp/gbt45314_ecall.csv
```

For tuning sweeps, keep each result CSV separate and compare the hard-floor metrics before promoting any preset. As of 2026-05-27, `--agc --ns-dry-blend 0.20` fixes the synthetic B2 no-speech noise-stability floor while preserving hard far-end ERLE floors, but double-talk remains blocked and must not be waived.

Exit code `0` means the software pre-compliance floors are met. Exit code `1` blocks release. Exit code `2` means floors pass but headroom targets still need tuning.

## Lab-Only Items

The following remain outside this software gate and must be measured on the vehicle/lab setup: HATS SLR/RLR, POI acoustic/electrical calibration, receiving-path frequency response, formal P.863 MOS-LQO, formal ETSI TS 103 558 listening effort, formal ETSI TS 103 802 echo impairment, and certified double-talk class grading.

## Consequences

- The existing `v0.3` customer-passed baseline remains preserved as the pre-gate state.
- A future release must pass this gate before being described as China eCall-ready.
- If the current chain fails strict initial convergence, that is a real tuning blocker, not a test looseness issue.
